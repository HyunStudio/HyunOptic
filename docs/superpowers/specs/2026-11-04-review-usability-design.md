# Review workflow usability and submission design

Baseline: main `870109d1a9566cd7d153eddb901cef963c4507d0`. The user requested review of an independent audit and then authorized full implementation and testing after design. This design records the assistant's implementation choices; it does not invent human acceptance, clinical results or event-period work.

## Intent and alternatives

Make a research reviewer able to identify an input, compare both model outputs, hold an unresolved case, resume, and export evidence without accidental deletion or unnecessary scanning. Keep the existing local Streamlit/PyTorch stack.

Considered: (A) patch buttons only: low cost but retains full-session rehash latency and stacked comparison; (B) split metadata listing from verified detail/actions plus focused UI changes: moderate change, preserves integrity at use; (C) replace the front end/store: excessive migration risk. Adopt B as the assistant recommendation under the user's instruction to complete implementation autonomously.

## Scope and contracts

1. Deletion confirmation belongs to a session and an active selection. Switching sessions, completing deletion or reopening must not authorize a different session. The action text identifies the session/case count; a failed deletion preserves the current selection and reports an error.
2. Session creation must work without Git installed. Resolve provenance from the application's own source repository, never the caller's working directory/outer unrelated repository. Missing Git, timeout, failed command or non-source install returns explicit unknown/version provenance. Do not trust arbitrary strings as commit IDs.
3. Unsupported image cases are terminal for that imported artifact: one clear explanation, no retry button or duplicate preview error. Operational/model failures on supported, intact input retain explicit retry. Integrity failures withhold previews and decisions and explain restore/new-session action.
4. Add lightweight metadata list and single verified case access. Keep existing `cases()` and export snapshots strict. The UI list exposes recorded state/ordering, explicitly not a fresh session-wide integrity audit. Selected detail and every consequential action verify relevant files; export verifies all files. Never label cached/stored metadata as freshly verified; no mtime/TTL cache replaces byte validation.
5. Store stable priority metadata when processing finishes, retain it for list ordering, clear it on retry/invalidation. Existing sessions without stored priority use a safe pending/unverified fallback; no silent mask trust. One selected-case detail reads only that case's evidence. Reuse verified in-memory masks within one detail call where feasible.
6. Give cases stable local labels (`Case 001`, original basename optionally shown locally). UUID remains identity and private/local names must never enter export. Duplicate names remain distinguishable. Review save + next advances only after successful revision-checked save; respects current filter/order; a final case shows completion without auto-reviewing anything. Preserve plain Save.
7. Compare source + primary overlay + comparison overlay in aligned columns, matching image coordinates and persistent model identity. Offer full-size single view for narrow screens/zoom. No misleading difference heatmap or probability. Existing measurable-but-unverified labels and domain limits remain visible.
8. Responsive header: wrap chips/badges, allow shrinking and long text, avoid fixed-height clipping. Check desktop, 768px, 390px, 200% zoom and keyboard-visible focus. No color-only status meanings.
9. Benchmark deterministic synthetic 20/200-input sessions; record bytes, repeats, environment, metadata-list versus strict full-list latency and hash/read counts. A proposed engineering target is metadata listing p95 <0.5s and selected-case verification independent of total session size on the tested machine. Report actual results including misses; do not equate automated latency to human task-time savings or independent patients.
10. Rewrite README opening into purpose/quick start/latest evidence; retain all older reports by links. Concise Devpost narrative includes user-provided personal motivation accurately, specific task and supported results. Add an actual step comparison; retain unmeasured human-time disclaimer. Repo description/topics may be updated if tooling permits. Keep merged historical branches; no deletion is necessary for entry readiness. No license grant is selected on the author's behalf; document existing rights and dependency/data limitations.
11. Prepare a new current-version demonstration outline/captions and actual synthetic UI evidence. Refresh demonstration media when feasible with exact source and edited/synthetic/AI disclosure; a continuous unedited recording is not an official requirement. Preserve historical video evidence, do not pretend older footage shows current changes. Never invent personal A4 review or event contributions. All November 4 changes are pre-event.

## Builder-check rulings

Verified detail owns exact verified source/mask byte snapshots; the UI renders those bytes without reopening paths. Stored priority is bound to prediction_set_hash and protocol_hash, cleared on invalidation/recovery; legacy rows remain unverified until strict detail/action. Metadata omits prediction artifacts/paths and identifies recorded status explicitly. verified_case requires matching session ID. Save-next uses pre-save ordered visible IDs and moves only on successful save; the final eligible case reports completion. Deletion resets on every session transition including A-B-A, not just one key per session. Primary/comparison slots retain model identity if a prediction is absent. Shared provenance also replaces vulnerable pipeline/repro lookups where needed; exact application source root must match Git toplevel, and installed packages have unknown commit.
