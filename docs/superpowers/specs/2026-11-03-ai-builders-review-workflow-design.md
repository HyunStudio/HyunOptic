# HyunOptic: Global AI Builder’s Challenge 상세 설계

작성: 2026-11-03 · 상태: 구현 전 설계 제안 · 대상: 로컬 연구용 검수 도구

## 1. 제품 목표와 결정 범위

안저 이미지에서 AI가 disc/cup 경계를 예측한 뒤, 연구자가 검토할 순서를 정하고 결과를 확인·보류하며 그 판단을 추적할 수 있게 한다. 핵심 가치는 ‘측정값을 만드는 것’에서 ‘측정값을 검토 가능한 연구 기록으로 만드는 것’으로의 확장이다.

1차 사용자는 안과 영상 연구자와 데이터 검수 담당자다. 진료·질환 진단·치료 판단은 범위 밖이다. 사용자와 검토한 세 접근은 모델 재학습, 검수 흐름 완성, 연구 설명 챗봇이다. 본 상세 설계는 직전 추천안인 검수 흐름을 구체화한다. 최종 제품 방향 승인을 대신하지 않는다.

- 목표: 이미지 묶음 입력부터 예측, 검토 사유 표시, 결정 저장, 재개, 내보내기까지 실제 동작.
- 목표: 모델 간 차이가 오류 발견에 도움이 되는지 별도 평가하고 실패도 보고.
- 제외: 경계 그리기 편집기, 자동 재학습, 임상 위험 점수, 환자 관리, 클라우드 협업, LLM 설명 생성.
- 실패로 간주할 결과: 검토 완료를 정답 인증처럼 표시, 실패 이미지 누락, 참고 주석을 우선순위 계산에 사용, 이전 모델의 검토 결정을 새 모델에 승계.
- 아래 수치·구조·기술 선택은 설계자의 제안이며 사용자 합의 또는 실험 결과로 간주하지 않는다.

## 4. 사용자 흐름과 기능 요구

### 4.1 검토 작업 생성

로컬 파일 다중 선택 또는 연결된 데이터셋에서 사례 선택. 신규 입력은 PNG/JPEG/단일 프레임 TIFF, 한 작업 최대 500건·개별 파일 30MB·해독 후 25MP를 초기 제한으로 제안한다. 다중 프레임 TIFF는 첫 프레임을 몰래 선택하지 않고 미지원으로 표시한다. 기존 Iowa 스테레오 실행은 별도 연구 스크립트의 과거 기능으로 구분한다.

재개 가능한 입력을 확보하기 위해 선택한 원본 바이트를 작업공간의 session별 `inputs/`에 익명 ID 파일명으로 복사하고 해시를 확인한다. 업로드 객체나 외부 경로의 지속성을 가정하지 않는다. 원본 복사본은 로컬에 보존됨을 작업 생성 전에 알린다. 전체 입력 2GB를 초기 상한으로 제안하며 생성 시 최소 `입력 합계의 2배 + 500MB` 가용 공간을 확인하고 실행 중 저장 오류도 처리한다. 이 사전 확인은 공간 부족을 완전히 예방하는 보장이 아니다. 세션 명시 삭제는 입력·예측·DB 이력을 함께 삭제하며 삭제될 건수를 표시한다. 자동 만료는 없다. 원본 선택 경로는 입력 복사 후 필수 필드가 아니며 업로드의 경우 null이다.

RGB와 회색조만 수용하고 회색조는 RGB 복제로 변환한다. RGBA·CMYK는 초기 버전에서 명시적으로 미지원 처리한다. EXIF 방향을 반영한 해독 RGB 픽셀 해시와 원본 파일 바이트 해시를 함께 기록한다. 확대·밝기 같은 표시 설정은 추론 입력을 바꾸지 않는다. zip 업로드는 범위 밖이다.

기본 모델은 기존 정책을 유지한 seed-43 baseline이며, 비교 모델은 seed-43 photometric follow-up을 제안한다. 이는 정확도 우승 모델 선정이 아니라 차이를 검토하기 위한 고정 쌍이다. 지원 입력은 color fundus이며 사용자가 확인한다. SLO/OCT/알 수 없음은 별도 탐색 모드에만 허용하고 지원 범위 밖 배지를 항상 유지한다. 모델 검증 실패는 작업 시작 전에 차단한다.

### 4.2 실행과 재개

CPU에서 한 이미지·한 모델씩 처리한다. 기존 Predictor는 CPU 경로를 유지하며 GPU 최적화는 뒤로 둔다. 시작 버튼 후 제한된 청크를 처리하고 결과를 즉시 디스크에 저장한다. 브라우저 재실행 때 자동으로 작업을 중복 시작하지 않는다. ‘계속 실행’으로 미완료 사례를 재개한다. 첫 모델만 성공한 사례는 완료 사례로 집계하지 않는다.

작업 취소는 현재 사례 종료 후 반영한다. 완료 사례는 보존하고 미처리 사례는 pending으로 남긴다. 재시작 시 processing 상태는 interrupted로 바꾸고 사용자가 재시도할 수 있게 한다. 원본 파일 또는 모델 식별이 달라지면 이전 캐시를 쓰지 않는다.

### 4.3 검토 대기열

각 사례에 처리 상태, 검토 사유, 기본 모델의 측정 상태, 검토 결정이 보인다. ‘전체/미검토/보류/실행 실패’ 필터와 순차·우선순위 정렬을 제공한다. 성공한 사례만 보이는 기본 필터를 금지한다. 표시된 총수는 성공·실패·미완료 합과 일치해야 한다.

순서는 다음의 사전식 키로 고정한다. 가중합이나 질병 위험 점수는 만들지 않는다.

1. 실행 실패 또는 입력 미지원: 복구 대기 그룹. 해부학적 오류 순위 평가에서는 별도로 집계.
2. 한 모델 이상 invalid_geometry: 측정 검토 그룹.
3. 두 모델 모두 geometry-valid: `max(1 - Dice_disc, 1 - Dice_cup)` 내림차순.
4. 동점이면 익명 case ID 순서. 결과와 평가에서 동점 개수도 보고.

모델 간 Dice는 원본 해상도의 후처리된 두 예측 마스크로 계산한다. 하나라도 비어 있으면 임의의 Dice를 채우지 않고 invalid_geometry로 분류한다. 두 모델의 vCDR 절대 차이는 보조 설명으로만 표시한다. 저차이가 정확함을 의미하지 않으며 차이에 ‘위험도’·‘신뢰도 %’라는 이름을 붙이지 않는다. 임의의 경고 임계값도 초기 버전에는 두지 않는다.

### 4.4 사례 확인과 검토 결정

원본 전체 보기와 예측 오버레이를 제공한다. 초기 화면은 전체 이미지이며 예측 위치로 자동 확대하지 않는다. 잘못 위치한 disc가 확대 화면에서 정상처럼 보이는 문제를 줄이기 위한 선택이다. 선택적으로 확대하고 기본/비교 모델 경계를 전환한다. 참고 주석은 사용자가 펼치는 별도 패널이며 추론·정렬 입력에서 배제한다.

검토 결정: `unreviewed`, `reviewed`, `held`. UI 문구는 ‘미검토’, ‘확인 기록’, ‘보류’. 확인 기록에는 ‘경계 정확성을 인증하지 않음’을 표시한다. 보류 시 사유를 하나 이상 고른다: 잘못된 위치, 경계 불일치, 영상 품질, 미지원 영상, 판단 불가, 기타. 기타에는 메모가 필수다. 수정·미검토로 되돌리기도 이전 이력을 남긴다.

측정값은 ‘모델 예측’으로 구분하고 기본·비교 모델 값을 분리한다. geometry-invalid이면 수치가 없다. 보류 사례의 모델 출력은 삭제하지 않지만 보류 배지를 붙이고, 선택한 검토 사례 목록에서는 제외한다. ‘확인 기록’만으로 측정값을 임상적으로 사용 가능하다고 표현하지 않는다.

## 5. 데이터 모델과 저장

저장 위치 제안: `HYUNOPTIC_WORKSPACE/review/` 또는 기존 기본 작업공간 `.hyunoptic/review/`. SQLite는 Python 표준 라이브러리를 사용한다. 단일 로컬 사용자, 동시 두 세션의 오래된 수정은 차단하는 범위다.

| 객체 | 주요 필드·불변 조건 |
| --- | --- |
| session | UUID, schema_version, created_utc, software_commit, input_modality, protocol_hash, ordered model identities, status |
| case | 익명 UUID, session_id, 원본/픽셀 SHA256, 로컬 원본 경로, 크기, 입력 상태, 순번 |
| prediction | case_id, model_identity, attempt_id, status, errors, measurement 또는 null, label artifact SHA256, preprocess identity |
| review | case_id, prediction_set_hash, state, reasons, note, revision, updated_utc |
| event | 단조 sequence, event_id, actor_local_alias, action, old/new state, prediction_set_hash, UTC |
| artifact | 상대 경로, SHA256, byte_size, artifact_type |

model_identity는 가중치 해시만이 아니라 검증된 bundle manifest·config·전처리·후처리·런타임 버전을 포함한다. prediction_set_hash는 픽셀 해시·순서 있는 모델 identity·프로토콜 해시·완료된 예측 artifact 해시로 계산한다. 바뀐 입력/모델/프로토콜은 새 session을 만들며 검토 상태는 자동 승계하지 않는다.

마스크는 원본 해상도 class-map PNG로 로컬 저장한다. 임시 파일 저장→같은 볼륨 atomic rename→DB 트랜잭션 커밋 순서를 쓴다. 파일이 없거나 해시가 다르면 결과를 사용하지 않는다. DB 저장 실패 시 화면에 저장 완료를 표시하지 않는다. 종료 시 남은 임시/미참조 파일은 격리하며 자동 결과로 채택하지 않는다.

검토 변경과 event 추가는 하나의 DB 트랜잭션이다. revision 비교로 다른 탭이 먼저 저장한 변경을 감지하고 새로고침을 요구한다. 이벤트는 앱에서 수정하지 않는 이력이지만 암호학적 서명·법적 감사 로그·변조 방지를 보장하지 않는다.

## 6. 내보내기 계약

기본 전체 검토 패키지: `session.json`, `cases.csv`, `predictions.csv`, `reviews.csv`, `events.jsonl`, `manifest.json`, 정적 `summary.html`. 원본 이미지·마스크·절대 경로·원본 파일명·메모·로컬 사용자명은 기본 제외한다. 메모 포함은 명시적 옵션이며 공유 전 검토가 필요하다. ZIP은 내보내기 전용이다.

- 전체 기록에는 실패·보류·미검토도 전부 포함한다. 선택한 확인 기록만 내보낼 때는 별도 파일로 만들고 전체 분모·제외 수·선택 조건을 함께 쓴다.
- metric은 없는 값에 빈 칸/null을 사용한다. 0으로 채우지 않는다. 기본/비교 모델·이미지별 처리 상태와 `no_reference`를 분리한다.
- manifest는 자기 자신을 제외한 모든 payload의 파일명·길이·SHA256을 기록한다. 별도 검증 CLI가 누락·변조·경로 이탈을 거절한다. 현재 공개 실험 manifest를 덮어쓰지 않는다.
- CSV 수식 시작 문자와 HTML escape를 처리한다. HTML은 스크립트·외부 네트워크 요청이 없는 정적 파일이다.
- 익명 ID·해시는 개인정보 비식별화를 보장하지 않는다. 공개 공유는 자동 실행하지 않는다.

## 7. 코드 구성 제안

`src/hyunoptic/review/`에 `schema.py`(타입/버전), `store.py`(SQLite), `runner.py`(순차 실행/복구), `priority.py`(순위/사유), `export.py`(정적 패키지), `evaluate.py`(참고 주석 기반 오프라인 평가)를 둔다. UI에는 `views/model_review_queue.py`를 추가하고 `app.py`의 experimental model 영역에서 연결한다.

기존 단일 이미지 추론은 그대로 두고 표시 도우미를 공유한다. `ui/state.py`의 session_state는 현재 선택 사례·표시 옵션만 저장하고 검토 기록의 원본 저장소로 쓰지 않는다. 새 로직은 Streamlit에 의존하지 않는 서비스 함수로 만들어 CLI에서도 검증한다. DB migration 세부와 청크 크기는 구현자가 결정하되 미지원 schema를 묵시적으로 덮어쓰지 않는다.

### 우선순위의 탐색적 평가

기존에 분석한 PAPILA holdout/Chákṣu/FairSeg 결과는 재사용 분석으로 공개하고 독립 확인 시험으로 부르지 않는다. 참고 주석이 없는 OLIVES/Iowa는 실행·측정 가능성만 평가한다. FairSeg SLO는 지원 밖 스트레스 분석이며 일반 fundus 성능과 합치지 않는다.

우선순위 공식·모델 쌍·평가 타깃은 실행 전에 protocol JSON과 해시로 고정한다. 1차 ‘큰 모델 오류’ 타깃은 기본 모델의 geometry-invalid 또는 기준 마스크 대비 disc Dice < 0.5 또는 cup Dice < 0.5로 제안한다. 이는 연구용 조작적 정의이며 임상 경계값이 아니다. PAPILA와 Chákṣu의 1차 참고 주석은 기존 `seg/evaluate.py`와 같은 expert 1이며 expert 2 기준은 별도 민감도 분석이다. PAPILA contour rasterization과 Chákṣu binary mask·reference 유효성 처리를 기존 평가 코드와 해시로 고정한다. FairSeg는 공식 Test disc/cup 마스크를 사용한다. 합의 마스크를 새로 생성하거나 독자 기준을 섞지 않는다.

모든 reference-valid 이미지가 분모다. 해독/추론 실패는 별도 운영 실패로 보고하고 성공 예측의 Dice=0으로 위장하지 않는다. 순위 효용은 추론 결과가 존재하는 집합에서 평가하며 제외 수와 운영 실패를 반드시 병기한다. geometry-invalid 기본 모델은 타깃 오류로 포함한다.

구체적으로 전체 입력 수·reference-valid 수를 먼저 보고하고, 순위 효용의 분모는 reference-valid이면서 **양 모델이 모두 추론 결과를 반환한** 사례로 고정한다. 이때 invalid_geometry는 결과가 반환된 경우이므로 포함하며, exception/error는 제외한다. 기본 모델만 성공하고 비교 모델이 실패한 사례는 별도 건수와 그중 기본 모델의 큰 오류 건수를 보고한다. 기본 모델 실패 사례도 별도 운영 실패로 보고한다. 따라서 조건부 순위 성능을 전체 입력의 오류 포착률로 표현하지 않는다. reference-invalid도 별도 분모로 기록한다.

- 상위 10%/20% 검토 예산(ceil)에서 큰 오류 recall, precision, 검토 건수, 오류 총수.
- 순차 순서 및 1,000개 고정 seed 무작위 순서와 비교. 동점은 case ID 기준 실제 제품 순서이며 동점 수를 공개.
- 환자 ID가 신뢰 가능한 경우 환자 단위 bootstrap 95% 구간. 그렇지 않으면 이미지 단위 기술 통계로 명시하고 환자 독립성을 주장하지 않는다.
- 추가로 기본 모델 geometry-invalid만 먼저 보는 단순 규칙과 비교하여 모델 2개 사용의 기여·추론 비용을 평가.
- 모델 간 일치하지만 큰 오류인 사례를 별도 표로 보고. 우선순위로 포착하지 못한 오류를 숨기지 않는다.

제안한 기능 유지 기준: 두 fundus 재분석 집합 각각에서 20% 검토 recall이 무작위 평균보다 높고, 단순 geometry 규칙 대비 모델 2개 사용의 추가 기여가 관측될 것. 이는 탐색적 유지 판단이며 일반화의 확증이 아니다. 만족하지 못하면 정렬 기능을 ‘효율 개선’으로 홍보하지 않고 모델 비교·측정 실패 필터·검토 기록만 주 기능으로 제출한다. 새 미사용 데이터의 독립 평가가 확보되면 모델/정렬을 고정한 뒤 별도 보고한다.

사람의 검토 전후 정확도·소요 시간은 실제 참여자·참고 정답·과제 설계가 있는 별도 연구가 있어야 주장한다. 개인 시연 시간은 사용자 연구로 부르지 않는다.

## 9. 배포·데이터·모델 준비

공개 코드와 실제 가중치 제공은 별개다. 현재 로컬 가중치를 이미 공개한 것으로 가정하지 않는다. 대회 전 학습 데이터별 이용 조건과 가중치 재배포 가능성을 검토하고 승인 가능한 아티팩트만 배포한다. 제한 데이터 원본·마스크·환자 ID는 저장소에 추가하지 않는다.

기본 경로는 합법적으로 취득한 로컬 자료와 모델을 사용하는 실행이다. 재배포가 불명확하면 실가중치를 공개하지 않고 공개 학습 코드·고정 config·데이터 취득 및 로컬 학습 절차·CPU 요구 사항을 제공한다. 심사자의 재현 비용을 제한 사항으로 명시한다. 권리 확인이 끝난 소규모 실제 예시를 확보할 수 없으면 합성 예시는 UI/실패 처리 시연으로만 쓰며 실제 AI 성능 증거와 섞지 않는다. 연구용 데이터의 공개 영상 표시 권한도 별도 확인한다. 이 확인은 실제 이미지·모델 배포와 데모 촬영의 선행 조건이다.

## 10. 접근성·사용성 요구
