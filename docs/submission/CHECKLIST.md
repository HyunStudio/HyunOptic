# Final publication checklist

The software preparation package is not itself a completed Devpost submission.

- [x] Working local input → prediction → review → reopen → export process.
- [x] Source/model identity checks and visible failure handling.
- [x] Synthetic 100-case interrupted batch and persisted review checks.
- [x] Private input/notes excluded from default exports; independent ZIP verification.
- [x] Separate disclosure of existing work, AI use and pre-event implementation.
- [x] Local real-model workflow smoke without patient data publication.
- [ ] Preserve the actual event-start version and record only genuine event-period changes.
- [ ] Submitter personally checks the frozen diff, results, disclosures and demonstration.
- [ ] Record and publish an actual 2–4 minute demo with permitted or synthetic imagery.
- [ ] Supply the actual public video URL and final GitHub commit/branch in Devpost.
- [ ] Confirm eligibility, team roster, data/display permissions and current official rules.
- [ ] Submit before the official deadline; do not mark submission complete beforehand.

No efficiency, clinical-performance, clinician-approval or organizer-endorsement claim should be added without supporting evidence.
