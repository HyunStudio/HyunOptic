# Repository rights and public demonstration

## Existing author policy

The package metadata in [`pyproject.toml`](../../pyproject.toml) states **"License not yet selected; all rights reserved"**. The repository README likewise says that no software license has been selected. This update preserves that status: it does not select MIT, Apache or another license, grant new reuse rights, or label the project open source. Public source access and an open-source license are separate matters.

The author can decide whether to grant a software license later. Keep repository metadata, README and any future license file consistent if that decision is made. This document is a record of the existing policy, not a substitute license or legal attestation.

## Third-party code, data and media

Python, PyTorch, Streamlit, NumPy, Pillow and other dependencies retain their own licenses. Installing dependencies does not transfer their ownership or grant rights to third-party research data. Any distributed dependency code or other third-party material must retain applicable notices and meet its own terms.

PAPILA, Chákṣu, RIM-ONE DL and other research sources retain their providers' access/use conditions. Permission to analyze a local dataset does not by itself establish public-display, redistribution or derived-weight rights. The private real-data model bundles are not provided by the public demo. [Access and dataset restrictions](MODEL_AND_DATA_ACCESS.md).

Use the project's generated synthetic images and locally trained synthetic models for public captures. Do not expose patient data, masks, identifiers, private research bundles, local account information or registration details. Credit any additional media and establish its display/publication rights before including it. A successful platform copyright check is an observed platform result, not proof of all rights.

## Event requirements and remaining choices

The [official event rules](https://global-ai-builders-challenge.devpost.com/rules), checked 2026-11-04, require public GitHub access to all project code and compliance with third-party licenses. They do not explicitly require an open-source license selection, deletion of merged branches, or a continuous unedited recording. Existing-project improvements are allowed with truthful disclosure of prior work and actual event-period changes. No organizer approval is inferred from these observations; recheck the rules and applicable terms when submitting.

Merged historical branches can remain. Preserve source commits, older reports and historical media so the submitted version and its development history can be understood.
